Dashboard — three registers

One committed direction: the dashboard is a ruled register with an attention gutter, not a deck of cards. All three comps share the same identity, tokens, type and copy. What differs is the structure an image can settle: whether priority is a separate band or the first group of one list, and whether the pipeline earns permanent screen on a phone. Rendered at the real surface viewport — 390 px, RTL, Fredoka + Archivo, live HTML, not a picture of a screen. Frames run past the fold so the second screenful is visible.

Three system changes applied in all three

You said the design system can improve. Three findings — the first is a defect, not taste.

1 · Split the red into signal and commit

#ec3013 cannot legally carry text on a fill: white on it measures 3.76:1, black 4.17:1 — both under the 4.5:1 body floor, so today's primary button and Won tag fail AA. Fix: #ec3013 keeps every line — gutter rules, focus ring, kanban stage 5, icon accents (3:1 is enough there). Filled surfaces that carry text move to accent-700 #ae1800 → 6.4:1. The identity survives; the discipline gets sharper: bright red marks, deep red commits.

lines · fills
2 · The status ramp has one more failure

proposal_sent pairs n-600 #7d7979 with n-100 text = 3.94:1. One step darker to n-700 #605d5d gives 5.97:1 and the ramp still darkens monotonically toward Won, so the greyscale-legible pipeline the system promises is intact.

was · now
3 · Attention needs tokens, not a screen

The gutter is the dashboard's spine, so it belongs to the system, not to one route: --lf-attention-now (accent, 2px), --lf-attention-drift (n-500, 2px), --lf-attention-none (transparent), plus --lf-gutter-w. The register row becomes a documented primitive that reminders, the activity timeline and the analytics breakdown all inherit — one row grammar in the whole product.
